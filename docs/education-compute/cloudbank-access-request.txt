PUBLIC OVERVIEW
The University of Arizona College of Information Science requests CloudBank Classroom access through ACCESS for a two-course pilot in [TERM / YEAR]: INFO 521: Introduction to Machine Learning (proposed) and LIS 671: Digital Curation and Digital Preservation (proposed). Approximately 80 students would use browser-based CPU workspaces for reproducible data analysis, small-model evaluation, metadata normalization, collection queries and portable research outputs. The pilot aims to reduce software setup barriers and improve continuity of access across different student devices. We will evaluate workspace access, assignment reproducibility, export/recovery and staff effort using aggregate results. Both courses will retain an equivalent small-data CPU fallback, with institution-supported oversight, data handling and end-of-term exports.

PLANNED WORK SUMMARY
We propose one 15-week teaching pilot preceded by six weeks of configuration/canary testing and followed by a two-week export/close period, subject to provider and ACCESS approval. The proposed INFO 521 component will use Python notebooks to clean synthetic tabular data, visualize patterns and validate small CPU models. The proposed LIS 671 component will normalize synthetic collection records, document metadata crosswalks, query an embedded SQLite catalog and export structured records with provenance. No GPU, external managed database or paid student account is necessary for required coursework.

We request persistent individual CPU workspaces for 80 students plus up to six course/technical staff accounts, institutional authentication, approved assignment distribution and a reproducible Python environment. The preferred student configuration is 2 vCPU, 6 GB RAM and an initial 5 GB home, or a provider-approved equivalent shown by rehearsal to run the assignments. Initial shared course data are modeled at 20 GB per course. Expand only after the canary demonstrates a justified need and the provider approves it. The college will designate course leads, primary/backup operators and support TAs, and will seek written operating commitments before classroom use; this draft does not claim those appointments or funds already exist.

A ten-volunteer canary will precede provider-approved concurrency testing, account isolation, assignment execution, saved-file restart/export, grading-receipt reconciliation, accessibility review and a restore to a different environment. We will maintain CPU/small-data alternatives and independently restorable copies in institution-approved destinations. Rosters and grades will remain in approved institutional/LMS systems. The educational project will have explicit closure/export dates; continuation requires a confirmed provider/ACCESS process rather than assumed extension.

Please confirm that the managed Classroom resource, rather than a general CloudBank commercial-cloud award, is appropriate; specify its accounting and credit/resource request amount. We can split the two courses into separate educational projects if ACCESS or the provider requires it.

RESOURCE JUSTIFICATION / AMOUNT
Planning workload: 80 students × 8 active workspace-hours/week × 15 weeks = 9,600 student workspace-hours; 2 vCPU each implies 19,200 CPU core-hours of active demand. A 25% usage allowance gives 12,000 workspace-hours / 24,000 CPU core-hours before provider orchestration/idle billing and staff use. These are workload descriptions, not CloudBank SUs or ACCESS credit conversion. Request an initial 5 GB home per student plus 20 GB shared data per course: 80 × 5 + 2 × 20 = 440 GB before staff homes and provider overhead. Core tabular/catalog inputs are bounded below 250 MB each; the home/shared allowance covers notebooks, multiple assignment copies, outputs and approved small projects. Measure usage in the canary and grow only for justified semester needs with provider approval. The earlier 20 GB-home / 2 TB Jetstream2 assessment is a larger planning scenario, not a minimum CloudBank requirement. Required GPU amount: none. Numeric CloudBank credit/resource amount remains to be supplied from the provider’s actual managed-Classroom accounting; do not enter the Jetstream2 VM model as CloudBank credits.
