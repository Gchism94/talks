What DS and MLIS could do.

Data science

Prepare/debug on CPU. For an authorized Modal test, package a small fixed-data training or inference function; record GPU type, cold/warm wall time, correctness, checkpoints and total charged CPU/memory/GPU usage.

General training needs a custom runtime, not only access to a provider’s model API. Keep the existing Kaggle/Colab notebooks and final ACCESS replay as the baseline.

Library and information science

Test rights-cleared public/synthetic OCR, document embeddings, metadata suggestions or retrieval. Separate model/API quality from the performance of our own code. Private holdings, patron data and course records need approved destinations.

Existing MLIS GPU code measures a projection/retrieval proxy; it is not a pretrained embedding or OCR quality benchmark. Checkpoint and export outputs; vendor storage is not a preservation repository.

Before any cloud canary.

  1. Use only an approved institutional payment arrangement or explicitly confirmed grant exception; require no personal/student card. No spending is authorized.
  2. Confirm current grant/credit eligibility, duration, three-seat workspace fit, allowed products, data destinations and provider-reviewed class/account terms. Never multiply one workspace allowance by 80 seats.
  3. Before any authorized run, review usage budget and net-charge spend limit separately; disable excluded paid APIs, unneeded schedules, warm containers and automatic purchasing. Verify the actual stop behavior.
  4. Pin code/image/data; measure build/start/warm time, CPU, GPU, memory, device/VRAM, preemption, checkpoints, outputs and charged units. API results do not measure a custom CUDA training workload.
  5. Export code, environments and results outside the vendor; retain authoritative grades/rosters in approved institutional systems. Replay representative CPU/GPU workloads on awarded ACCESS resources before class.
  6. Keep all added setup/support inside Greg’s ten-hour weekly envelope, with TA/lead effort separate. Defer the option if funding, support or privacy conditions fail.

Zero cash budget. Greg has ten hours/week total; TA and course-lead hours are separate. No new staffing costs or paid fallback are assumed. Campus AWS stays CPU component-testing only; all thirteen classroom gates remain planned.
